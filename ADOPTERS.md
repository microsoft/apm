# APM adopters

Organizations and projects using Agent Package Manager (APM).
Inclusion records usage, not endorsement. Entries describe only the scope
the adopter has agreed to make public.

See the [CNCF definition of an adopter](https://github.com/cncf/toc/blob/main/FAQ.md#what-is-the-definition-of-an-adopter).

## Adopters

| Organization | Type | Adoption Level | Description |
| ------------ | ---- | -------------- | ----------- |
| EPAM | Consultancy, Contributor, End-User Organization | Production | Uses, actively contributes to, and consults on APM. |
| Sopra Steria | End-User Organization | Production | Uses APM. |

Type and adoption level are optional. Blank fields mean that the information
is not publicly specified, not that usage is absent.

## Add or update an entry

Submit a pull request with one row per organization or project:

- **Organization:** the name approved for public listing. An approved industry
  description may be used instead when the organization needs to remain anonymous.
- **Type (optional):** CNCF End-User Member, End-User Organization, Service
  Provider, Project, Consultancy, or Contributor. Choose based on how APM is
  used; more than one type may apply.
- **Adoption Level (optional):** Production, Dev/Test, Trialing, or Evaluating.
  Leave blank if the stage is not confirmed or cannot be disclosed.
- **Description:** a short, factual statement approved for publication.
  "Uses APM." is sufficient when further details cannot be shared.

Confirm that the organization permits the proposed public name and wording.
Do not include private correspondence, contact details, internal system names,
customer identities, or deployment details without permission.

Keep the adopter list sorted alphabetically by organization.

List direct adopters, not a service provider's customers solely because they
indirectly benefit from APM. Keep entries accurate as usage changes.
