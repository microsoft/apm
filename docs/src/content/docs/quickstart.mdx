---
title: Give every teammate the same skills, plugins and MCP servers
description: Install a skill, a marketplace plugin and an MCP server with one tool, commit two files, and every clone gets the same agent setup. Five minutes.
---

import { Steps, FileTree, Aside, LinkCard, CardGrid } from '@astrojs/starlight/components';

You share a repository with teammates who use coding agents, and everyone's setup is a little
different. In five minutes you will add a skill, a plugin from a marketplace and an MCP server,
commit two files, and watch a fresh clone get the same setup, checked against a lockfile.

**You need:** APM ([install it](../getting-started/installation/)), a git repository, and GitHub
Copilot or Claude Code.

<Steps>

1. **Pick the agents you use.**

   ```bash frame="terminal"
   apm init -y --target copilot,claude
   ```

   This writes `apm.yml`, the manifest that lists what your agents load. `--target` names the
   agent tools (harnesses) APM writes for: `.github/` for GitHub Copilot, `.claude/` for Claude
   Code.

2. **Install a skill**, the same way `npx skills add` does.

   ```bash frame="terminal"
   apm install vercel-labs/agent-skills --skill deploy-to-vercel
   ```

   ```text frame="none"
   [i] Targets: claude, copilot  (source: apm.yml)
     [+] vercel-labs/agent-skills #main @1a2c79d4
     |-- 1 skill(s) integrated -> .agents/skills/, .claude/skills/
     [!] 1 dependency unpinned: vercel-labs/agent-skills -- apm.lock.yaml pins the
   resolved commit; add #tag in apm.yml to track releases on update
   [*] Installed 1 APM dependency in 6.5s.
   ```

   This skill follows the repository's `main` branch, so APM points out that the lockfile
   records the exact commit you got, `1a2c79d4`. Teammates get that commit until you run
   `apm update`. Add `#<tag>` to the install to follow tagged releases instead.

3. **Install a plugin from a marketplace.** A marketplace is a published list of plugins;
   this is Anthropic's.

   ```bash frame="terminal"
   apm marketplace add anthropics/claude-code --ref v2.1.328
   apm install commit-commands@claude-code-plugins
   ```

   ```text frame="none"
   [+] anthropics/claude-plugins-official/plugins/commit-commands#main
   ...
     |-- 3 prompts integrated -> .github/prompts/
     |-- 3 commands integrated -> .claude/commands/
   [*] Installed 1 APM dependency in 6.2s.
   ```

   One plugin, written in each harness's own format: commands for Claude Code, prompts for
   GitHub Copilot. `apm.yml` records where the plugin's files actually live, so the lockfile
   can pin them.

4. **Add an MCP server.**

   ```bash frame="terminal"
   apm install --mcp io.github.github/github-mcp-server --transport http
   ```

   ```text frame="none"
   [i] Targeting declared targets from apm.yml: claude, copilot
   |  [+]  io.github.github/github-mcp-server -> Claude, Copilot (configured)
   [*] Configured 1 server
   ```

   One line in `apm.yml`, and APM writes the configuration each harness reads. No hand-edited
   JSON, and the same server on every machine.

5. **Commit the manifest and the lockfile.**

   ```yaml title="apm.yml"
   dependencies:
     apm:
       - git: vercel-labs/agent-skills
         skills:
           - deploy-to-vercel
       - git: https://github.com/anthropics/claude-plugins-official
         path: plugins/commit-commands
         ref: main
     mcp:
       - name: io.github.github/github-mcp-server
         transport: http
   ```

   ```bash frame="terminal"
   git add apm.yml apm.lock.yaml .gitignore
   git commit -m "Add agent dependencies"
   ```

   `apm.yml` says what you asked for. `apm.lock.yaml` records what you got: the exact commit of
   each source and a SHA-256 hash of every file APM wrote.

   ```yaml title="apm.lock.yaml" {3,5-6}
   - repo_url: vercel-labs/agent-skills
     ...
     resolved_commit: 1a2c79d4e6c4a2283dc2c614b6538cbe1ed5ca62
     deployed_file_hashes:
       .agents/skills/deploy-to-vercel/SKILL.md: sha256:418ca2a60d35...
       .claude/skills/deploy-to-vercel/SKILL.md: sha256:418ca2a60d35...
   ```

   APM added its download cache,
   `apm_modules/`, to `.gitignore`. Committing the files it wrote is optional: any clone
   rebuilds them from the lockfile
   ([should I commit them?](../concepts/how-apm-works/#common-questions)).

6. **Be your teammate.** Clone the repository into a second folder and install from the
   lockfile.

   ```bash frame="terminal"
   git clone . ../teammate && cd ../teammate
   apm install --frozen
   ```

   ```text frame="none"
   |  [+]  io.github.github/github-mcp-server -> Claude, Copilot (configured)
   ...
   [*] Installed 2 APM dependencies and 1 MCP server in 1.5s.
   [i] Deployed files verified against apm.lock.yaml.
   ```

   `--frozen` installs exactly what the lockfile records and fails if `apm.yml` disagrees. Use
   it in CI. Your teammate now has:

   <FileTree>
   - .agents/skills/deploy-to-vercel/SKILL.md
   - .claude/
     - commands/commit.md and 2 more
     - skills/deploy-to-vercel/SKILL.md
   - .github/prompts/commit.prompt.md and 2 more
   - .mcp.json
   </FileTree>

7. **Check the files against the lockfile.**

   ```bash frame="terminal"
   apm audit
   ```

   ```text frame="none"
   [+] Replayed 2 package(s)
   [+] No drift detected
   [*] 8 file(s) scanned -- no issues found
   ```

   `apm audit` rebuilds what the lockfile describes and compares it with the files on disk. It
   also flags hidden Unicode characters that can carry instructions a reviewer cannot see.

</Steps>

## What you just did

- **Declared** a skill, a plugin and an MCP server in `apm.yml`, once, for two harnesses.
- **Locked** them in `apm.lock.yaml`: exact commits and per-file hashes.
- **Verified** a fresh clone against the lockfile. A file that changes shows up as drift.

<Aside type="note" title="What APM does not do">
APM controls what gets installed. It does not run your agent or limit what the agent does at
runtime; your harness does that. A lockfile records what you installed, not that it is safe.
See [How APM works](../concepts/how-apm-works/).
</Aside>
