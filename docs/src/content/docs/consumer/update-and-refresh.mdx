Use this page to take new versions of your agent packages without surprises.
A plain `apm install` never moves a version: it replays `apm.lock.yaml`.
Versions change when you run `apm update`, edit `apm.yml`, or merge a
pull request that does one of those.

## See what is outdated

```bash frame="terminal"
apm outdated
```

`apm outdated` compares each locked dependency with its upstream and changes
nothing. Add `-v` to list the newer tags. An unreachable source shows as
`unknown`.

## Update on purpose

Preview, then apply:

```bash frame="terminal"
apm update --dry-run
apm update
```

`apm update` prints a plan (added, updated, removed, unchanged) and asks
before changing anything; the default answer is No. Name packages to limit
the update to them (`apm update contoso/review-skills`). In scripts and CI, pass
`--yes`. `apm update` also revalidates any marketplace behind a dependency and fails
rather than use stale data.

"Latest" means the newest version your `apm.yml` allows:

| Entry in `apm.yml` | What `apm update` does |
|---|---|
| `#^1.1.0` (range) | Moves to the highest matching tag |
| `#main` (branch) | Moves to the branch tip |
| `#<40-char SHA>` (commit) | Moves to the commit of the newest annotated release tag and adds the tag as a comment |
| `#v1.1.0` (exact tag) | Stays on that tag; edit it to move |

To jump to a release outside your range, edit `apm.yml` and run `apm install`.

## Review the lockfile diff

The lockfile diff is the change your reviewers approve. When Ben releases
`contoso/review-skills` 1.2.0, Ana's update pull request shows:

```diff title="apm.lock.yaml"
 - repo_url: contoso/review-skills
-  resolved_ref: v1.1.0
-  resolved_commit: 3f2a9c1...
+  resolved_ref: v1.2.0
+  resolved_commit: b71e04d...
   deployed_files:
     - .agents/skills/security-review/SKILL.md
+    - .agents/skills/security-review/references/owasp.md
```

Read it for:

- **New packages**: a new `repo_url` is a new transitive dependency.
- **New files**, especially hooks, MCP servers and scripts. If your project
  uses the approval gate, they stay parked until someone runs
  [`apm approve`](../approve-executables/).
- **Changed sources**: a different host or repository for the same name.

## After a lock bump, run `apm install`

A pull request that changes `apm.lock.yaml` does not change the files on
anyone's machine. After you pull it, run:

```bash frame="terminal"
apm install
```

CI rebuilds from the lockfile with `apm install --frozen`; see
[Run in CI](../run-in-ci/).

## Dependabot

Dependabot opens pull requests for git dependencies in `apm.yml` and
regenerates `apm.lock.yaml` when one exists:

```yaml title=".github/dependabot.yml"
version: 2
updates:
  - package-ecosystem: "apm"
    directory: "/"
    schedule:
      interval: "weekly"
```

- Tag pins move to the newest semver tag, including package-scoped tags such
  as `review-v1.4.0`.
- SHA pins move to the newest annotated, non-prerelease release tag, with the
  tag added as a comment.
- Branch pins change the lockfile, not `apm.yml`.
- It runs `apm lock`, which writes the lockfile without deploying files.

It skips object-form entries (`git:`, `path:`), entries without a ref, local
paths, Azure DevOps and `http://` sources, and `mcp:` entries. Reference:
[Dependabot supported ecosystems](https://docs.github.com/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories#apm).

## Renovate

Renovate's `apm` manager reads every `apm.yml` and updates entries pinned with
an exact `#ref`:

```json title="renovate.json"
{
  "extends": ["config:recommended"]
}
```

With `pinDigests` (part of `config:best-practices`), it keeps a SHA pin and its
tag comment current. When `apm.lock.yaml` exists, Renovate refreshes it by
running `apm install`, so the `apm` CLI must be available to Renovate (for
example `binarySource=global` on a self-hosted runner). Reference:
[Renovate apm manager](https://docs.renovatebot.com/modules/manager/apm/).

## Verify

```bash frame="terminal"
apm outdated
```

```text frame="none"
[*] All dependencies are up-to-date
```

## Update the APM CLI binary

Updating APM itself is separate from updating packages: see
[Install APM](../../getting-started/installation/).

:::tip[Other options]
`apm lock --update` refreshes refs in the lockfile without deploying.
`apm install --refresh` re-resolves refs and downloads again, bypassing the
cache. Every flag: [`apm update`](../../reference/cli/update/) and
[`apm outdated`](../../reference/cli/outdated/).
:::
