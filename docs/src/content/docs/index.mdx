APM is the dependency manager for the agent supply chain: one manifest, one lockfile and one
org policy for the skills, plugins and MCP servers your agents load, with the harnesses and
marketplaces you already use.

No account and no registry. Packages come from git: GitHub, GitHub Enterprise, Azure DevOps,
GitLab. [Other install options](./getting-started/installation/).

**Works with your harness**, the agent tool that reads the files: GitHub Copilot, Claude Code,
Grok Build, Cursor, OpenCode, Codex, Gemini CLI, Windsurf and Kiro.

## Skills, plugins and MCP servers, one tool

```bash frame="terminal"
# A skill, the way npx skills add does it
apm install vercel-labs/agent-skills --skill deploy-to-vercel

# A plugin from a marketplace
apm marketplace add anthropics/claude-code
apm install commit-commands@claude-code-plugins

# An MCP server, configured for every harness in the project
apm install --mcp io.github.github/github-mcp-server --transport http
```

Commit `apm.yml` and `apm.lock.yaml`. A teammate clones the repository and gets the same setup:

```text frame="none"
$ apm install --frozen
[*] Installed 2 APM dependencies and 1 MCP server in 1.5s.
[i] Deployed files verified against apm.lock.yaml.
```

[Try it in five minutes](./quickstart/).

## MCP servers without hand-edited JSON

Every harness keeps MCP servers in its own file and format: a shared `.mcp.json` for Claude
Code and GitHub Copilot, `.cursor/mcp.json` for Cursor, `.codex/config.toml` for Codex, and more.
Declare a server once in `apm.yml` and APM writes each of those files for you, on every machine.

- **One declaration, every harness.** Add a harness later and the same servers follow.
- **Secrets stay out of the repository.** Write tokens as `${VAR}` references; APM translates
  them into each harness's own syntax, so the harness reads the value when it starts the server.
- **No surprise servers.** A self-defined server that arrives through someone else's package is
  held back until you declare or approve it.

[Add MCP and LSP servers](./consumer/install-mcp-servers/).

## Copies drift silently. Locked dependencies show you the drift.

A skill pasted into ten repositories becomes ten skills. Declare it once instead, and APM records
exactly what you got.

  <Card title="apm.yml -- what you asked for">

      apm:

APM writes each harness's own format, so nobody changes tools. Keep your harness and your
marketplaces; APM adds the manifest, the lockfile and the policy underneath.

## From one repository to your whole organization

Teams that run coding agents at scale end up building the same thing: a marketplace of approved
agent capabilities, published by a central team and installed by many repositories. APM is the
dependency layer under that marketplace.

| Step | What you turn on | What you get |
|---|---|---|
| 1 | `apm.yml` and `apm.lock.yaml` in each repository | The same files on every machine |
| 2 | `apm install --frozen` and `apm audit --ci` in CI | CI fails when the files and the lockfile disagree |
| 3 | An organization `apm-policy.yml` | One place to allow or deny sources, MCP servers and executables |
| 4 | An `executables:` policy, approvals and an exported inventory | Hooks and MCP servers need an approval before they deploy; a CycloneDX or SPDX list on demand |

APM governs what gets installed. Your harness governs what runs.
[Read the security model](./enterprise/security/).
